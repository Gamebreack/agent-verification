# 03 — Adjudication-policy fixes from run 2026-09-28

## Outcome (approved)

- AC-1: `.agents/skills/verify/references/adjudication.md` gates a finding on
  re-deriving its mechanism from the evidence alone, independent of reviewer
  agreement — e.g. "would the mechanism still hold if the reviewers' shared
  premise were false?" — and states that echoing a caller-supplied input is
  not a disclosure.
- AC-2: `adjudication.md` states a written severity rule distinguishing
  NON_ISSUE from OPTIONAL for an absent or weak test on otherwise-correct
  code (e.g. required evidence present and surviving mutation contrived vs.
  the contract's required_evidence naming the test and it being absent, or
  the suite failing to distinguish two plausible implementations of a named
  requirement).

Decided: the eval harness stays strict — an expected `PASS` will not accept
`PASS WITH NOTES` (operator decision, 2026-09-28). This was AC-3; it is now
closed, not an open criterion.
